# Контракт API

Форму карточки тренда пишет ядро, отдаёт бэкенд, рисует фронтенд. Пока три
направления представляют её по-разному, расхождение вскроется в последний день.
Поэтому сначала фиксируется форма, потом пишутся эндпоинты.

Образец с настоящими числами: **`data/index/sample-index.json`**, 58 КБ. Группы
в нём взяты по темам OpenAlex, а не нашей кластеризацией, зато ряды по годам,
организации, страны и ссылки посчитаны по выгруженному корпусу. Верстать и писать
эндпоинты можно по нему прямо сейчас; когда заработает ядро, подменится только
источник. Пересобирается командой `uv run python scripts/make_sample_index.py`.

Ключи полей латиницей: их набирать в коде фронтенда и бэкенда.

## Устройство

Тяжёлый расчёт идёт офлайн, результат — один файл индекса на единицы мегабайт.
Бэкенд читает его при старте и держит в памяти.

**База данных не нужна** — ни СУБД, ни миграций, ни объектного отображения.
Всё, что сложнее чтения файла, придётся объяснять на защите.

Во внешние API на запросе не ходим. Демонстрация не должна зависеть от сети:
если в зале ляжет интернет, показывать будет нечего.

## Эндпоинты

| | |
|---|---|
| `GET /directions` | какие направления посчитаны |
| `GET /trends?direction=ai&limit=15` | топ трендов, карточки целиком |
| `GET /trends/{id}` | одна карточка |
| `GET /trends/{id}/documents?page=1` | документы группы: первоисточники, с постраничной выдачей |
| `GET /validation` | проверка на прошлом: метрика, сравнение с базовым подходом, негативные контроли |
| `GET /report/{id}` | выгрузка отчёта |

`/validation` обязателен: результат проверки на прошлом — главный слайд защиты.
Если его нет в API, фронтенд не сможет его показать, и обнаружится это накануне.

`/report` обещан в заявке.

## Карточка тренда

```json
{
  "rank": 1,
  "id": "T11689",
  "title": "Adversarial Robustness in Machine Learning",
  "summary": "одно предложение",
  "motivation": "какую проблему решает и какое преимущество даёт",
  "case_example": {
    "title": "Explaining and Harnessing Adversarial Examples",
    "url": "https://doi.org/10.48550/arxiv.1412.6572",
    "year": 2014, "venue": "arXiv", "cited_by": 8146
  },
  "sources": [{ "title": "...", "url": "...", "year": 2017, "venue": "...", "cited_by": 4806 }],
  "first_year": 2010,
  "works_total": 924,
  "series": [{ "year": 2010, "works": 33, "per_10k": 5.1 }],
  "features": { "normalized_growth": 7.96, "acceleration": 2.1,
                "organizations": 412, "countries": 38 },
  "score": 1.0,
  "top_organizations": ["Google (United States)", "Stanford University"],
  "top_countries": ["US", "CN", "GB"]
}
```

`series` и `features` нужны не для красоты: без них карточка остаётся утверждением
без доказательства, а спросят именно «почему это тренд». `per_10k` — доля темы
в корпусе того же года; без нормировки растёт всё подряд.

`normalized_growth` и `acceleration` — разные вещи, и нужны обе. Первое отвечает
«во сколько раз тема выросла», второе — «ускоряется ли она сейчас». Тема, растущая
ровно вдвое каждый год, и тема, которая годами стояла и только что рванула, по одному
росту неразличимы, а зарождающаяся — это вторая.

Мотивация, кейс-пример и блок `validation` в образце помечены
`"is_placeholder": true`. Ядро заменит их на настоящие.

## Ответ целиком

Кроме `trends` в файле лежат `index_version`, `slice_id` и `built_at`. Их стоит
возвращать в каждом ответе: иначе через неделю не разобрать, на каких данных
сделан скриншот.

Поле `is_sample` показывает, что отдаётся образец, а не результат. На защите
оно должно быть `false`.
