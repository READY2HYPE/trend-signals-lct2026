# Формат данных

Что лежит в выгрузке и как это читать. Схема объявлена в коде один раз —
`src/collect/schema.py` для научных работ и `src/collect/arxiv.py` для препринтов —
и по ходу работы не меняется.

## Где что лежит

```
data/raw/openalex/year=2010/part-000.parquet     научные работы, разложены по годам
data/raw/arxiv/set=cs/part-000.parquet           препринты, разложены по разделам
data/sample/openalex-sample.parquet              40 тысяч работ для быстрых прогонов
data/aggregates/works-by-year.json               сколько всего работ вышло в каждом году
data/manifest.json                               что выгружено, с контрольными суммами
```

Формат parquet: таблица хранится по столбцам и сжата. Можно прочитать один столбец,
не разбирая файл целиком, — на миллионе записей это разница между миллисекундами
и минутой.

## Научная работа

| Столбец | Тип | Что это |
|---|---|---|
| `id` | строка | `W2124531089`, идентификатор OpenAlex |
| `doi` | строка | ссылка вида `https://doi.org/…`, есть у 74% |
| `arxiv_id` | строка | `2104.14399`, ключ связи с препринтами |
| `title` | строка | заголовок |
| `abstract` | строка | краткое содержание, есть у 73% |
| `publication_year` | целое | год |
| `publication_date` | строка | `2015-03-12` |
| `date_is_placeholder` | да/нет | дата — ровно 1 января, то есть день неизвестен |
| `type` | строка | `article` или `preprint` |
| `language` | строка | `en`, `ru`, … |
| `is_oa` | да/нет | доступна ли работа открыто |
| `cited_by_count` | целое | сколько раз процитирована |
| `primary_topic` | `{id, name, score}` | главная рубрика и уверенность в ней от 0 до 1 |
| `primary_subfield_id` | целое | подобласть, у нас `1702` |
| `topics` | список `{id, name, score}` | все рубрики; по ним считается переход между областями |
| `institution_ids` | список строк | организации авторов, без повторов внутри работы |
| `institution_names` | список строк | их названия |
| `institution_countries` | список строк | коды стран, `US`, `CN`, … |
| `author_count` | целое | сколько авторов |
| `venue` | строка | журнал или площадка |

Список процитированных работ не сохраняется: он огромный и для наших признаков не нужен.

## Препринт

| Столбец | Тип | Что это |
|---|---|---|
| `id` | строка | `2104.14399` или старый вид `cs/0501001` |
| `created` | строка | **дата первой версии** — ради неё источник и берётся |
| `updated` | строка | дата последней правки |
| `title`, `abstract` | строка | заполнены практически всегда |
| `categories` | список строк | `cs.LG`, `stat.ML`, … |
| `primary_category` | строка | первая из них |
| `doi` | строка | есть только у 2% |
| `authors` | список строк | имена |
| `author_count` | целое | сколько авторов |

## Как посмотреть глазами

Parquet — не текстовый файл, двойным кликом он не откроется. Три способа, от простого
к гибкому.

**Команда в проекте.** Ничего доставлять не нужно, работает сразу после `uv sync`.
Если полной выгрузки нет, читается подвыборка из репозитория.

```
uv run python -m src.collect.peek                       десять работ подряд
uv run python -m src.collect.peek --year 2018 -n 3      конкретный год
uv run python -m src.collect.peek --search transformer  поиск по заголовку
uv run python -m src.collect.peek --topic graph         поиск по теме
uv run python -m src.collect.peek --preprints           то же по препринтам
uv run python -m src.collect.peek --stats               сводка
uv run python -m src.collect.peek --columns             список столбцов
```

**SQL прямо по файлам.** DuckDB читает parquet без загрузки в память и без установки
в проект — `uv` подтягивает его на один запуск:

```
uv run --with duckdb python -c "import duckdb; print(duckdb.sql('''
  SELECT publication_year, count(*), round(100.0*count(abstract)/count(*),1)
  FROM read_parquet('data/raw/openalex/*/*.parquet')
  GROUP BY 1 ORDER BY 1'''))"
```

## Как читать

Чтение всего корпуса или отдельных лет:

```python
import pyarrow.parquet as pq
from src.collect import config, schema

cfg = config.load()

works = pq.read_table(cfg.raw / "openalex", schema=schema.WORKS)   # весь срез, ~4 ГБ в памяти
sample = pq.read_table(cfg.sample / "openalex-sample.parquet", schema=schema.WORKS)
```

Обычно весь корпус не нужен. Нужные столбцы и годы читаются в разы быстрее и не съедают
память:

```python
# тексты за 2010–2021: срез для проверки на прошлом, 951 115 работ
root = cfg.raw / "openalex"
t = pq.read_table(root, schema=schema.WORKS,
                  columns=["id", "title", "abstract", "publication_year"],
                  filters=[("publication_year", "<=", 2021)])
```

Список папок в `read_table` передать нельзя — он принимает файлы, а не каталоги.
Либо `filters=`, как выше, либо перечислить файлы:
`[str(p) for y in range(2010, 2022) for p in (root / f"year={y}").glob("*.parquet")]`.

Препринты читаются одной функцией, которая убирает повторы: работа, помеченная сразу
в двух разделах arXiv, приходит из каждого.

```python
from src.collect import arxiv
pre = arxiv.read_preprints(cfg)
```

Связь между источниками — по `arxiv_id`, а не по DOI:

```python
ids = set(pre["id"].to_pylist())
linked = [a for a in works["arxiv_id"].to_pylist() if a in ids]
```

Дальше удобнее в pandas: `t.to_pandas()`. Весь корпус целиком переводить не стоит,
только нужные столбцы.

## О чём помнить при счёте

Записи без аннотации остаются в корпусе намеренно: в кластеризацию они не идут, но нужны
в счётчиках по годам — это знаменатель для нормировки. Отсеивать их следует на шаге
текстов, а не при чтении.

Знаменатель считается с той же фильтрацией, что и числитель. Почему именно так и что ещё
искажает счёт — [03-данные.md](03-данные.md), раздел «Что показал замер».

Уверенность рубрики (`primary_topic.score`) бывает низкой: у 12% записей ниже 0,5,
и туда попадают работы из смежных тем. Порог задан в `config/slice.yaml`.

Даты с `date_is_placeholder` годятся для годовых рядов и не годятся для помесячных.

Срез заморожен. Пересобранная своими руками копия сверяется с манифестом:
`uv run python -m src.collect.manifest --check`.
