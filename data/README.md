# Данные

Полная выгрузка в репозитории не хранится: GitHub не принимает файлы больше 100 МБ,
а корпус занимает больше гигабайта. Порядок величин —
[../docs/05-разработка.md](../docs/05-разработка.md).

| Путь | Что | В репозитории |
|---|---|---|
| `index/` | готовый индекс: кластеры, признаки, карточки | да |
| `sample/` | подвыборка 20–50 тыс. записей для разработки | да |
| `aggregates/` | число работ по годам, знаменатель для нормировки | да |
| `ground-truth/` | внешний список прорывов и негативных контролей | да |
| `manifest.json` | состав среза: файлы, размеры, контрольные суммы | да |
| `raw/` | полная выгрузка | нет |
| `embeddings/` | векторы работ, из них считаются группы | нет |

**Бэкенду и фронтенду нужен только `index/`.** Корпус им не требуется вообще.

## Что качать

С `git clone` приходит всё, кроме `raw/` и `embeddings/`. Они лежат по одной ссылке
несжатыми — можно зайти и взять только нужное, а не четыре гигабайта разом:

**https://cloud.mirea.ru/index.php/s/MTtdpd9bfAEL59i**

| Что | Вес | Когда нужно |
|---|---|---|
| `embeddings/sample/` | 75 МБ | разработка конвейера: подвыборка проходит его за минуты |
| `embeddings/openalex/` | 2,8 ГБ | итоговый прогон группировки по всему корпусу |
| `raw/` | 1,3 ГБ | признаки, проверка на прошлом, сверка полноты среза |

Скачанное кладётся в `data/` в корне проекта под теми же именами. Корпус после этого
сверяется:

```
uv run python -m src.collect.manifest --check
```

Контрольные суммы должны сойтись. Расхождение в данных даёт самую трудноуловимую ошибку
«у меня работает, у тебя нет», поэтому сверка не по желанию.

Векторы контрольными суммами пока не покрыты. Разойтись они могут молча — другая
точность или версия модели дают другие числа, а на вид не отличить, — поэтому свои
считать заново не стоит, если нужен тот же результат.

Выгрузить самому теми же командами, что в README, тоже можно — они продолжаются после
обрыва и упора в суточный лимит. Но для итогового результата это не замена: OpenAlex
дописывает записи задним числом, поэтому свежая выгрузка даст почти тот же срез, а не
тот же, и контрольные суммы не сойдутся.

Срез заморожен: после выгрузки он не меняется. Иначе проверка методологии на прошлом
теряет смысл — вчерашние результаты перестают воспроизводиться.
